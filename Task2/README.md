## Проблемы безопасности

- Внутренние потоки данных между IT-продуктами контролируются не системно.
- Нет уверенности в том, что все текущие бизнес-процессы компании соответствуют законодательным нормам. 
- Ограничения по передаваемым данным в основном обусловлены бизнес-процессами между взаимодействующими IT-продуктами.
- Со стороны систем обработки данных нет ограничений на доступ к данным.
- Есть несколько точек регистрации нового клиента, координации между этими точками нет.
- Системы PropDevelopment используют API управляющих компаний без единых политик по безопасности и без системного контроля за передаваемыми данными.
  - Контракты API содержат категории данных, которые явно предоставляют персональные данные.
  - Некоторые контракты позволяют внешним пользователям выполнять действия и получать данные, к которым у них не должно быть доступа.
- Недавно были изменения в составе руководителей IT-команд, из-за чего нарушился процесс передачи информации между командами. В какой-то момент стало понятно, что специалисту по ИБ передают не все решения и изменения. 
- Специалист по ИБ один на всю компанию. Высокий bus-factor, также он может не справляться со всеми "вызовами".

## Описание системы

У компании доменная структура. Каждый домен отвечает за часть бизнеса.

Список систем:

1. Система продаж
2. Система ЖКУ
3. Система Финансов
4. Система хранения данные

Описание возможных проблем:

1. Общий сервис аутентификации на 2 системы (Система продаж - Система ЖКУ) компрометация одной из систем приведет к тому что скомпрометирована и вторая
2. Данные всех систем хранятся в общей системе хранения, что делает урон компании максимальным в случае компрометации
3. Сложность в реализации принципа минимальных привилегий, потенциально пользователи одной системы могут получить доступ к другой системе (из за общего сервиса auth-service-1)
4. Непонятно под каким пользователем идет взаимодействие между Витриной продаж и client-crm-app и др сервисами, кажется взлом витрины продаж дает доступ ко всей системе продаж и даже за ее пределы, тоже относится к витрине сервисов для собственника
5. Непонятно как разделяются права клиентов и собственников, кажется при желании клиент может получить доступ к системе ЖКУ 
6. Firewall контролирует только клиентов, непонятно как подключается менеджеры\аналитики, например если напрямую к client-crm-app то им также доступны все остальные системы что создает угрозу безопасности
7. Взаимодействие напрямую через JDBC может создавать проблемы безопасности
8. При передаче данных через Change Data Capture (CDC) возникают специфические угрозы безопасности, связанные с перехватом, искажением или утечкой изменений данных.
9. Отсутствует мониторинг и логирование, системы выявления аномалий и системы предупреждений

(далее согласно проверочному листу)

## Разделы для включения в проверочный лист

1. Управление доступом - в компании по заданию и в ходе анализа были выявлены замечания в организации работы с учетными записями, распределением прав и организацией сервисов. В рамках этого раздела мы также должны проанализировать в т.ч. и сервисы, для устранения обозначенной проблемы - Некоторые контракты позволяют внешним пользователям выполнять действия и получать данные, к которым у них не должно быть доступа.
2. Соответствие требованиям законодательства - ввиду постановки, имеются вопросы к тому, что все текущие бизнес-процессы компании соответствуют законодательным нормам
3. Анализ и мониторинг - в системе кажется имеется полное отсутствие механизом выявления атак
4. Данные - важно четко понимать, какие данные в компании имеются, их типы, как и куда передаются, сохраняются и как защищаются. В частности одна из проблем обозначена как - Контракты API содержат категории данных, которые явно предоставляют персональные данные.
